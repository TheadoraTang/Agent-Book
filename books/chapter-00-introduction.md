# 引言：从一个会聊天的程序，到一个会做事的 Agent

## 本章摘要

### 新概念

- **Agent**：一个会围绕目标继续往下做事的程序，不只是回一句话。
- **项目驱动学习**：先让一个小项目跑起来，再把新知识一层层加到它身上。
- **TravelPlanAgent**：本书一直打磨的旅行规划助手，后面每章都会让它多一点本事。

### 产品功能增量

- 这一章先不写代码。你会知道这门课要把 TravelPlanAgent 从命令行聊天程序，慢慢做成一个能查信息、能规划、能检查结果的 Agent。

欢迎来到《**Agent 系统设计与实战开发**》。

如果你翻开这本书，是因为最近总听到“Agent”“智能体”“大模型应用开发”这些词，却又隐隐觉得它们有点虚、有点远，那很正常。

Agent 这个概念确实容易被讲得很大：自主决策、多工具协作、长期记忆、任务规划、多智能体系统……听上去像是刚开始就要造一台复杂机器。

但这本书不会从“宏大系统”开始。

我们会从一个非常小、非常具体、可以一步步跑起来的项目开始：**TravelPlanAgent，一个旅行规划助手**。

它一开始不会很聪明。它可能只是一个能在命令行里调用大模型聊天的小程序。然后，我们会在每一章给它增加一点能力：

- 让它知道自己是旅行规划助手；
- 让它能记住最近几轮对话；
- 让它能调用天气工具；
- 让它能根据工具结果继续思考；
- 让它能检索旅行知识库；
- 让它能拆解任务、规划路线、检查行程；
- 最后，再用成熟 Agent 框架把它写得更规范。

这样安排的好处是，你一开始不用硬啃一个完整 Agent 系统，而是亲手看着它一点点长出能力。

## 这本书会学习什么

这本书的主线是：**先理解 LLM，再构建基础 Agent，最后使用成熟框架实现更规范的 Agent**。

整个学习过程分成四个部分。

| 部分 | 你会学习什么 | TravelPlanAgent 会发生什么变化 |
| --- | --- | --- |
| 第一部分：与 LLM 协作 | LLM 基础、API 调用、Prompt Engineering、Structured Output | 从“能调用模型聊天”变成“有固定角色和输出约束的助手” |
| 第二部分：基础 Agent 构建 | 上下文、Tool Calling、Think-Act-Observe、RAG、任务规划 | 从“会回答”变成“会查信息、会观察结果、会规划旅行任务” |
| 第三部分：使用成熟 Agent 框架 | LangChain、LlamaIndex、Pydantic AI 等框架思路 | 用框架重新实现 TravelPlanAgent，理解框架带来的规范和便利 |
| 第四部分：高级 Agent 知识 | Memory、Monitoring 等更接近真实项目的问题 | 了解一个 Agent 从课堂练习走向真实应用时还需要补齐什么 |

这本书不打算把概念单独放在玻璃柜里讲。

每个重要概念都会尽量回到同一个问题上：**它能让 TravelPlanAgent 多做什么？**

比如：

- 学 API 调用，是为了让程序能真正连接 LLM；
- 学 Prompt，是为了让 Agent 有清晰角色和稳定输出；
- 学上下文，是为了让它能连续对话；
- 学工具调用，是为了让它不只靠“脑补”，还能获取真实信息；
- 学 RAG，是为了让它能使用我们提供的旅行知识库；
- 学任务规划，是为了让它能处理“帮我安排一次旅行”这种更复杂的需求。

## 为什么选择 TravelPlanAgent

旅行规划是一个很适合学习 Agent 的项目。

因为它既不抽象，也不简单。

当一个用户说：

```text
我想下周去成都玩三天，预算不高，喜欢吃小吃，不想太赶。
```

一个真正有用的旅行规划助手，不能只是随便列几个景点。它需要理解很多信息：

- 用户要去哪里；
- 大概玩几天；
- 预算是否有限；
- 喜欢什么类型的体验；
- 是否需要查询天气；
- 路线安排是否顺路；
- 每天行程会不会太满；
- 是否需要根据用户反馈调整计划。

这正好对应 Agent 开发里的核心问题：理解需求、维护上下文、调用工具、观察结果、拆解任务、生成方案、再检查方案。

所以 TravelPlanAgent 不是随便选的例子。它像一条线，把这本书里很多看似分散的知识串起来。

## 不要有畏难心理

如果你现在还不太会写复杂项目，没关系。

如果你对大模型 API、Prompt、RAG、工具调用这些词只是听说过，也没关系。

这本书默认你不是一上来就什么都懂的人。学习 Agent 开发，本来就不应该从“我必须先懂完所有概念”开始。

更好的方式是：

1. 先跑通一个最小版本；
2. 看见它真的能工作；
3. 再理解它为什么这样工作；
4. 然后每次只改一小块；
5. 最后把这些小能力连成一个完整系统。

你会发现，很多看起来高级的能力，拆开之后并没有那么神秘。

比如“Agent 会调用工具”，可以先理解成：

- 模型判断自己缺少什么信息；
- 程序调用一个函数或 API；
- 把工具返回结果再交给模型；
- 模型根据新信息继续回答。

比如“Agent 有记忆”，一开始也可以很朴素：

- 把最近几轮对话保存下来；
- 下一次请求时一起发给模型；
- 模型就能知道刚才聊过什么。

复杂系统通常就是这样长出来的：先有能跑的骨架，再一层一层补上能力。

## 你应该怎样学习这本书

建议你用一种“做项目”的方式读这本书，而不是只把它当成概念手册。

每一章都可以按这个节奏来：

1. 先理解这一章要解决 TravelPlanAgent 的什么问题；
2. 再理解这一章的新概念；
3. 然后运行示例代码；
4. 接着可以自行修改一个很小的局部；
5. 最后观察 Agent 的行为发生了什么变化。

**不要害怕报错**。

报错也不用急着当成失败。它更像程序在提醒你：“这里和你想的不一样。”
尤其在 Agent 开发里，调试不仅包括代码调试，还包括 Prompt 调试、上下文调试、工具结果调试和模型输出调试。

你以后会慢慢习惯一种新的开发感觉：  
不是只问“代码有没有执行”，还要问“模型看到了什么、它为什么这样回答、我该给它什么额外信息”。

这正是 Agent 开发最有意思的地方。

## 本书的最终目标

学完这本书，你不一定会立刻做出一个能替代真人旅行顾问的商业系统。

但你应该能做到这些：

- 理解 LLM 应用和传统程序的关键差异；
- 知道如何通过 API 在程序中调用大模型；
- 能设计基本 Prompt，让模型按角色和格式工作；
- 能维护多轮上下文；
- 能让 Agent 调用外部工具；
- 能理解 Think-Act-Observe 这种 Agent 工作循环；
- 能给 Agent 增加一个简单 RAG 知识库；
- 能把复杂任务拆成多个子任务；
- 能看懂成熟 Agent 框架大致在帮你处理什么。

更重要的是，你会形成一种判断力：

> 什么时候应该让模型生成，什么时候应该调用工具，什么时候应该检索资料，什么时候应该让程序规则来兜底。

这比记住某一个框架的某一个函数更重要。
